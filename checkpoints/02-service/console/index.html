Pipeline

state persisted after every node

Each pill is one entry in nodes.NODES. The graph saves state and the next node's name after every step — which is why killing uvicorn mid-run and restarting it resumes instead of losing the ticket. repair_plan and handle_failure stay dim unless something goes wrong.

Approval required

the run is paused

Nothing is refunded until you click. The run is not sitting in memory waiting — it stopped, and the decision restarts it at execute_actions (approve) or draft_customer_reply (reject). Refunds carry an idempotency key, so a double-click cannot pay twice.
